# A4P HAR consumer obfuscation rules.
#
# The A4P wire format and every signature are computed over the canonical
# JSON of the intent objects (docs/canonical-json-spec.md): the codec
# walks the real property names, so the field names kept below are
# signature-bearing bytes. A consuming app that enables
# -enable-property-obfuscation without these keeps renames the SDK's
# properties and produces JSON that no other A4P implementation (Java
# SDK, server) can parse or verify, while responses it receives fail to
# parse against renamed keys.
#
# This file ships with the HAR (merged into the consuming app's rules
# automatically). The kept names cover the SDK's full public property
# surface — anything the app's obfuscator must NOT rename because a
# pre-compiled SDK object or a cross-boundary call depends on it:
#   - model fields (wire format, signature payloads)
#   - namespace members (A4p.*/A4pCodec.*: app call sites resolve
#     against the pre-compiled HAR bytecode, which keeps these names)
#   - enum members (app accesses on the pre-compiled enum objects)
#   - Signer.sign / SignatureVerifier.verify (app implements, SDK calls)
#   - VerificationResult / HTTP envelope / thrown BusinessError fields
#     (code, message, data, valid)
#
# Trade-off: kept names are never renamed anywhere in the consuming app,
# including its own fields with the same spelling. That is the inherent
# price of a wire-format SDK.
#
# Keep in sync with obfuscation-rules.txt and with the public surface in
# Index.ets and src/main/ets/models/: every new wire-visible field,
# namespace member, or enum member MUST be added here in the same change.
# The golden wire-key test (A4pCodec.test.ets, GoldenWireKeys describe)
# fails if a wire field name drifts.
