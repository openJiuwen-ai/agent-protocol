# IIAP 文档维护规则

最后更新：2026-09-18

## 1. 入口与权威来源

- `IIAP/docs/zh/README.md` 是完整中文 SDK 文档入口并维护主题归属表；`IIAP/docs/en/README.md` 是英文 Quickstart 和关键参考入口。
- 当前源码和通过的测试定义已实现行为；已确认的产品规范定义目标行为。
- JSON Schema 是跨语言 wire contract 的权威来源，TypeScript/Python 类型和示例必须与其一致。
- 历史提交、proposal 和 JiuwenSwarm 审计只证明历史能力，不自动成为 SDK 规范。
- 同一协议、算法、矩阵或配置只能有一个权威位置，其他页面只能摘要并链接。

## 2. 实现与文档同步

修改以下内容时，必须在同一变更中更新主题归属表指定的权威文档：

- 公共 API、Schema、错误码、状态机和默认策略；
- A2UI 组件、事件、聚合、阈值、surface 生命周期和触发条件；
- packet、decision、assistance、feedback、prompt 和用户响应；
- 隐私、日志、安全更新、版本和兼容范围；
- 安装、配置、Demo、测试命令和验收标准。

## 3. 冲突、过期与不确定内容

- 发现文档与实现冲突时，核对适用版本、代码和测试，直接修正原定义，不追加相反说明。
- 重复内容收敛到唯一权威页面，其余位置改成链接。
- 过期材料移入 JiuwenSwarm 的 `docs/zh/iiap/archive/` 或删除；归档页必须标明适用基线和替代入口。
- 不得把未发布包、API 或命令描述成已经公开可用。
- 无法从代码、测试、Schema 或确认规范判断时，记录到内部审计并向用户提出，不得猜测。

## 4. 写作与验证

- 每份中文文档记录 `最后更新：YYYY-MM-DD`，英文文档记录 `Last updated: YYYY-MM-DD`；语义变化时更新日期，纯排版变化不刷新。
- 公共 API、兼容范围和安全边界变化时，英文 Quickstart/关键参考与中文权威页必须同步；英文页不复制整套算法权威定义。
- 对外文档只保留稳定结论，不包含 session 过程、内部争论或模型思维过程。
- 必要推导使用“约束 → 设计 → 结果”，避免把完整上下文拆成大量互相依赖的小页面。
- 示例 JSON 必须可解析；代码和命令应由真实 Demo 或自动化验证支持。
- 更新后运行文档链接/日期检查，并核对路径、包名、函数名、枚举、版本和示例。

## 5. 变更检查清单

- [ ] 找到主题归属表指定的唯一权威页面。
- [ ] 区分当前源码候选、正式发布和历史行为。
- [ ] 同步 API、Schema、测试、示例和兼容矩阵。
- [ ] 删除冲突和重复定义。
- [ ] 更新语义变化页面的日期。
- [ ] 验证链接、JSON、代码片段和命令。
- [ ] 将未决事项留在内部材料，不写成对外结论。
